Agent Team（5角色 · 职责 · 决策边界）

角色职责类型决策边界
数据查询Agent通过MCP从ES查询网点通/BI数据Agent只能查ES已有数据，不做归因；数据异常标记退回
归因分析Agent基于知识库生成归因报告初稿Agent出初稿供人审，不自主决定归因结论
改进跟踪Agent推送任务、跟踪进度、关联下次复盘Agent自动预警升级，但不自主决定升级给谁
干部（部门长/总监）触发复盘、审核数据、确认归因、分配措施人最终决策权：是否采纳归因、如何分配任务
FD团队反馈归因质量，提供真实案例，参与知识库迭代人归因对错判断权；决定知识库更新方向

协作模式（3种类型 + 升级机制）

Agent自主执行（人只触发）
  • 步骤2 数据获取：干部触发 → Agent查ES → 返回数据
  • 步骤7 任务推送：措施确认 → Agent推送OA/企微/邮件
  • 步骤8 跟踪闭环：Agent跟踪 → 到期提醒 → 预警升级
人审Agent输出（Agent初稿 → 人确认）
  • 步骤4 归因分析：Agent生成报告 → 干部审核 → 通过/退回
  • 步骤6 改进措施：Agent生成建议 → 干部确认分配
人工操作（Agent不参与）
  • 步骤1 触发复盘：干部发起或响应预警
  • 步骤3 数据审核：干部确认数据完整性
  • 步骤5 归因确认：干部最终判断归因合理性

升级机制：归因错误 → 入知识库 → FD团队复盘 → 迭代模型  |  未完成改进项 → Agent自动预警 → 升级给上级  |  Agent无法处理 → 标记异常 → 退回人工

工作流冻结版（8步骤 · 三类节点）

步骤输入输出节点类型执行说明流向/关键规则
1. 触发复盘复盘任务/异常预警复盘指令人工操作干部收到任务或系统预警，发起复盘→ 步骤2
2. 数据获取复盘指令结构化数据自动化数据查询Agent通过MCP从ES查询→ 步骤3
3. 数据审核结构化数据确认数据人工确认干部审核数据完整性和准确性通过→4；退回→2
4. 归因分析确认数据+知识库归因报告初稿人审+Agent归因分析Agent基于知识库生成多维度归因→ 步骤5
5. 归因确认归因报告确认归因人工确认干部审核归因合理性（初期60-70%）通过→6；退回→4
6. 改进措施归因+建议改进清单人审+Agent改进跟踪Agent生成建议，干部确认分配→ 步骤7
7. 任务推送改进措施+责任人推送通知自动化Agent通过OA/企微/邮件推送任务→ 步骤8
8. 跟踪闭环措施清单+进度闭环状态自动化Agent跟踪进度，下次复盘自动关联完成→归档；未完成→预警
