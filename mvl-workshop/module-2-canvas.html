2模块产出

👤 用户与使用场景

层级角色使用场景
直接用户基层干部（所长/县区负责人）做本县区复盘，找改进动作，给所长安排任务
直接用户中层干部（区域经理）汇总多县区复盘，推动跨部门协同改进
受益者+决策者高层领导看真实数据，校准战略与执行偏差

共5类角色：直接用户×2 + 受益者（职能部门）+ 决策者（高层领导/IT部门负责人）

◆ 核心需求

基层干部：看懂数据（不用手动导）、学会复盘（AI引导）、找到动作（具体改进建议）
中层干部：快速汇总（不逐个看报告）、找根因（跨部门归因）、推动协同（让其他部门配合）
高层领导：看到真实（不想看美化数据）、一杆子插到底（全局→门店级）、校准战略

! 痛点清单（有数据支撑）

导数据耗时：每次复盘准备2小时，干部陷入"取数-做表-写报告"事务性工作
覆盖率低：仅30%~40%，多维报表容易看漏，很多维度的问题没被发现
改进闭环率低：仅5%，事后才发现甚至预警不了，复盘结论无法落地
归因不准：销量波动涉及促销/缺货/竞品等多因素，人工难以准确定位根因
部门墙：各职能部门只管自己的KPI，跨部门归因做不了，"各付各的盘"
层层上报失真：信息在传递过程中被过滤美化，领导看到的不是一手数据

★ 最重要的结果

基层干部："我能提前预警问题，给所长明确的任务安排"
不是"做完报告"，而是"发现问题并提前预警"
中层干部："我能快速定位问题区域和根因，推动跨部门协同"
不是"汇总报告"，而是"找到共性问题"
高层领导："我能看到真实情况，校准战略方向"
不是"听汇报"，而是"一杆子插到底看真实数据"

⊞ 当前工作流

基层干部复盘流程（3.5~5小时）

收到复盘任务 → 手动导数据2h → 看数据找问题30min~1h → 写复盘报告1~2h → 上报（信息失真） → 等反馈（闭环率5%）

总耗时：3.5~5h | 覆盖率：30%~40% | 闭环率：5% | 重复率：10%

中层干部复盘流程（2~4天）

收集县区报告 → 手动汇总1~2天 → 跨部门沟通1~2周 → 写区域报告半天 → 上报高层

总耗时：2~4天 | 跨部门归因成功率：极低

高层领导看复盘流程

等层层上报1~2周 → 看汇总报告（信息失真） → 想知道细节（问不到） → 决策（基于失真信息）

信息失真度：高 | 穿透能力：无
