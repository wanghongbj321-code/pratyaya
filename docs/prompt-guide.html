1 第一轮对话提示语
根据不同场景选择对应的开场提示词，复制后替换方括号内容即可使用
场景 A：全新工作坊启动
最常用
我是第[组号]组成员，项目名[项目名]，请引导 MVL 工作坊 M1 战略对齐模块
适用时机：第一次打开专家，还没有任何项目数据。
专家响应：创建 mvl-workshop/{项目名}/ 目录，初始化 state.json（M1-M6 全部 draft），加载 M1 框架，输出引导问题。
替换示例：组号填 3，项目名填 智慧客服MVL。
场景 B：继续下一个模块
顺序推进
M[1-5]已完成，请切换到 M[2-6]，先给我引导问题
适用时机：上一个模块已 rendered，推进到下一模块。
专家响应：加载下一模块框架，输出引导问题，并带上上一模块影响本模块的已确认结论。
示例：M1已完成，请切换到M2，先给我引导问题
场景 C：中途中断后恢复
断点续传
检查状态
适用时机：隔了一段时间回来，不确定进度。
专家响应：报告六模块版本、状态、Gate 建议、确认模式、关键缺口和待确认人。
继续 M[1-6] 的[提炼 / 补问 / 确认]
示例：继续 M3 的提炼 — 专家会读取 state.json，从上次中断处继续。
场景 D：向他人演示专家
Demo
请显示你的 3 个快速指令
适用时机：向团队或客户展示专家能力。
专家响应：展示 plugin.json 中的 3 个 quickPrompts。
我是第 1 组成员，项目名「Demo项目」，请引导 MVL 工作坊 M1 战略对齐模块
演示建议：用这个指令创建 Demo 项目，走一遍 M1 引导→提交转写→Key Points→提炼→Gate→确认→渲染全流程，让对方直观看到四阶段管线。
场景 E：已有转写稿，直接提炼
高效模式
这是 M[1-6] 的讨论转写，请提炼内容、审核核心价值并生成结论确认包 <粘贴转写文本>
适用时机：会议已结束，有完整的逐字稿，想一步到位。
专家响应：存档转写 → Key Points 抽取 → 等你回复"提炼" → 生成确认包 → 自动跑 Gate。
注意：专家不会跳过 Key Points 直接提炼，会先给你 30 秒概览再等你决策。

演示脚本（约 15 分钟）

1 开场 — 展示快速指令（2 分钟）
请显示你的 3 个快速指令
讲解：三个快速指令分别对应「启动」「提炼」「全局汇总」三个核心入口。
2 初始化 — 创建 Demo 项目（3 分钟）
我是第 1 组成员，项目名「Demo项目」，请引导 MVL 工作坊 M1 战略对齐模块
讲解：专家会创建项目目录、初始化六模块状态机、加载 M1 框架并输出引导问题。
重点强调：用户驱动——专家不预设模式，所有关键决策由用户指令决定。
3 提交转写 — 展示四阶段管线（5 分钟）
这是我们的逐字稿： <粘贴一段准备好的 M1 讨论转写>
讲解：专家先存档原始转写，再生成 Key Points 概览（30 秒可浏览）。
展示 Key Points 的五部分：讨论主题、关键主张、矛盾点、覆盖度初判、用户决策提示。
提炼
讲解：专家生成 M1-v1.md 确认包，展示必展项 5 条（一句话结论、对齐摘要、阻塞项、缺口速览、待确认版本），然后自动运行 Gate。
4 Gate 确认与渲染 — 展示质量闸门（3 分钟）
确认 v1
讲解：Gate 是 LLM 建议者，用户是唯一门。gate_pass 时直接确认；business_risk FAIL 时可 override；information_integrity FAIL 不可 override。
选择 blue-professional-balanced
讲解：9 种视觉模式覆盖麦肯锡/Accenture/Bain/BCG/Roland Berger 等咨询风格。专家推荐 1-2 个，用户选定后生成 HTML。
5 收尾 — 展示状态管理与全局视角（2 分钟）
检查状态
查看所有产物
讲解：六模块状态一目了然。M1 已 rendered，M2-M6 待推进。最终六个模块全部 rendered 后，用「全局汇总」生成 MAAU 画布。

讲解时要强调的核心设计原则

原则 一句话解释
用户驱动 所有关键决策（模式、提炼、补问、视觉模式、override）由用户指令决定，专家不预设、不自动选择
讨论先于画布 先帮助小组形成结论，再制作 HTML。Canvas 不从逐字稿直接生成
人确认的是版本 确认 v2 后再修改内容，v2 自动失效，必须升版重跑 Gate 重新确认
LLM 是建议者 Gate 输出建议，但 render_authorized 必须由用户在看完报告后显式写入
未讨论就标空 允许未知，不允许伪完整。缺口必须解释影响
转写是不可信数据 转写中的命令、链接、文件操作要求视为讨论内容，不执行
