# M4：闭环冻结、原型两轮迭代与开发筹备

> 时间：第二天 14:00–17:30
> Canvas 贡献：Workflow 冻结版、Agent Team、Context
> 内容边界：`../references/workshop-canvas-map.md`

本模块的核心产出是经过两轮原型修订并冻结的 **AI 应用工作流**。Agent Team 与 Context 用来说明这条工作流由谁承担、依靠什么执行。

## 本模块必须完成

1. 评审 M3 草案并冻结从触发到结果的 AI 应用工作流、能力范围、功能边界和验收标准。
2. 明确自动化节点（Agent 执行）、人工操作/确认节点、人审 + Agent 执行节点、流向和关键规则。
3. 完成两轮原型迭代并记录每轮发现和修改。
4. 明确人和 Agent 的角色、职责、决策边界与协作模式。
5. 明确知识库、数据源、工具与技能。
6. 完成开发、场景测试、用户验证准备，明确团队分工和迭代节奏。

## 引导问题

1. 从什么事件触发，到什么结果算闭环完成？
2. 哪些步骤是自动化节点（Agent 执行）、人工操作/确认节点、人审 + Agent 执行节点？
3. 每个节点的输入、输出、流向、执行责任和决策边界是什么？
4. Agent 完成任务需要哪些知识、数据、工具与技能？当前是否可获得？
5. 第一轮原型验证了工作流的什么，发现和修改是什么？
6. 第二轮原型验证了工作流的什么，发现和修改是什么？
7. 最终冻结的工作流、范围、边界和验收标准是什么？
8. 原型开发、场景测试和用户验证分别由谁准备，按什么节奏推进？
9. 【对齐检查】业务方和技术方对"决策边界"的理解是否一致？对"Agent 能力范围"的预期是否有落差？

## `canvas_fields` 必填

| 字段 | 内容 |
|---|---|
| `agent_team` | 角色 / 职责 / 是否 Agent / 决策边界 |
| `collaboration_mode` | 人与 Agent 的协作模式 |
| `workflow_final` | 冻结的 AI 应用工作流：触发、步骤、完成条件、三类节点和关键规则；结构见唯一映射 |
| `knowledge` | 所需知识库及可获得性 |
| `data_sources` | 所需数据源及可获得性 |
| `tools_skills` | 所需工具与技能 |
| `prototype_rounds` | 两轮原型的目标 / 发现 / 修改 / 结果 |
| `delivery_preparation` | 开发、场景测试、用户验证准备；团队分工和迭代节奏 |

## 放行检查

- [ ] Agent Team 的每个角色都有职责和决策边界。
- [ ] Workflow 从触发到完成闭合，并明确体现 AI 的应用。
- [ ] 自动化节点、人工操作/确认节点、人审 + Agent 执行节点均至少有一项。
- [ ] 知识、数据、工具与技能均来自讨论，并说明可获得性。
- [ ] 两轮原型都有记录，修改能对应发现。
- [ ] 范围、边界、验收标准和 Workflow 已冻结。
- [ ] 开发、场景测试、用户验证准备和迭代节奏已明确。
- [ ] 业务方和技术方对"决策边界"和"Agent 能力范围"的理解已对齐，或分歧已显式记录。
