# M4 框架：人机分工与上下文冻结（D2 下午 14:00–17:30）

> 对应日程：MVL闭环冻结、AI原生原型两轮迭代与开发筹备。
> MAAU 落点：**Agent Team（人+Agent）** —— 角色 / 职责 / 是否Agent / 决策边界；**Context（上下文）** —— 知识库 / 数据源 / 工具；Workflow 冻结定稿。
> 方法来源：`references/methods/00-global-framework.md`（MAAU Canvas 六板块定义）、`references/methods/05-sandwich-workflow.md`。核心理念：「不要造一个大模型，要造一百个各司其职的小闭环」；三明治工作流（Silicon 执行 → Carbon 复核 → Carbon 决策）。

## 讨论支架（引导师用）

| 环节 | 时间盒 | 产出 |
|------|--------|------|
| MVL 定义对齐：一个 Intent、一条 Workflow、一组可验证指标 | 25 min | 统一口径 |
| Canvas 六字段落笔：Intent→User→Agent Team→Workflow→Context→Validation | 45 min | Canvas V1 |
| 原型 Round 1（Happy Path）：正常样本端到端，主持人按脚本扮演 Agent | 35 min | 原型 V1+测试记录 |
| 反馈 1：四分类+严重度（理解偏差/缺失输入/人工介入点/体验问题） | 20 min | 修改清单 |
| 原型 Round 2（Exception Path）：四类异常样本 | 25 min | 原型 V2+Canvas V2 |
| 冻结：范围、边界、验收标准定稿；砍掉清单 | 25 min | 冻结版 |

## 引导问题清单

1. 链路里的每个角色：谁是人（Carbon）、谁是 Agent（Silicon）？各自负责什么？
2. 每个 Agent 的**决策边界**：能自己决定什么（执行层）？什么情况必须升级（复核/决策层）？
3. Agent 干活需要什么知识？（制度/SOP/模板/案例/历史数据）知识现在在哪、什么形态？
4. 数据从哪里来？（系统/文件/API）现在能不能拿到？谁负责开通？
5. 需要哪些工具/技能？（检索/OCR/发消息/写系统……）
6. 原型 Round 1：Happy Path 跑通了吗？反馈四分类各收到什么？
7. 原型 Round 2：四类异常样本（缺失字段/规则冲突/非标准业务/低置信度）表现如何？
8. 冻结决定：范围是什么？**砍掉了什么**、为什么？（砍掉清单显式记录）

## 提取字段

| 字段 | 说明 | 必填 |
|------|------|------|
| team[] | 角色表：角色 / 职责 / 层(S执行·C复核·C决策) / 决策边界（可自决/须升级） | 是 |
| collabMode | 协作模式一句话（谁主导、人在哪些点把关） | 是 |
| knowledge[] | 知识库：名称 / 内容 / 来源 / 现状 / 维护人 | 是 |
| dataSources[] | 数据源：名称 / 内容 / 获取方式 / 可获取性(●有 ◐要建 ○盲区) | 是 |
| tools[] | 工具/技能：名称 / 用途 | 是 |
| prototypeRounds[] | 两轮记录：轮次 / 样本类型 / 发现（四分类+严重度） / 修改 | 是 |
| frozenScope | 冻结范围 + 砍掉清单（含原因） | 是 |
| workflowFinal | Workflow 冻结版（相对 M3 草案的修订点逐条标注） | 是 |

## 质量检查清单（及格线）

- [ ] 每个 Agent 角色有明确决策边界（可自决什么 + 必须升级什么）
- [ ] 每个数据源标注可获取性（●今天就有 / ◐需要建设 / ○盲区）
- [ ] 异常样本至少含 1 个真实翻车案例
- [ ] 砍掉清单显式记录且附原因，不许「默默消失」
- [ ] V2 每处修改能对应一条测试反馈（防方向漂移）

## 陷阱（引导时提醒小组）

Canvas 填成功能清单（每字段追问：业务结果是什么？）/ 主持人演成「万能 Agent」（脚本外一律回答：我做不到，转人工）/ 异常样本不够狠 / V2 改太多方向漂移。
