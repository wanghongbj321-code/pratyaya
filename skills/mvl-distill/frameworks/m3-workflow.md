# M3：闭环目标定义、HMW 拆解与方案方向锁定

> Canvas 贡献：回填 Intent；形成 Workflow 草案
> 内容边界：`../references/workshop-canvas-map.md`

## 本模块必须完成

1. 用 HMW 拆解已经确认的核心用户问题。
2. 确立 MVL 核心目标、能力指标、验收标准和边界。
3. 锁定 AI 方案方向。
4. 规划从触发到结果的 AI 应用工作流、三类节点与分层验证维度。

## 引导问题

1. 基于 M2 的核心用户问题，我们如何能在明确场景中改善最重要结果？
2. MVL 的核心目标是什么？
3. 闭环从什么事件触发，到什么业务结果算完成？
4. AI 应用工作流有哪些步骤，每步的输入、输出和流向是什么？
5. 哪些是自动化节点（Agent 执行），哪些是人工操作/确认节点，哪些是人审 + Agent 执行节点？
6. 哪些关键规则决定流程流向、升级或停止？
7. 能力指标和验收标准是什么？
8. 方案方向是什么，为什么适配当前场景？
9. 后续分别从哪些维度验证？
10. 【对齐检查】业务方认为的"闭环"和技术方认为的"闭环"边界是否一致？对"自动化"和"人工"节点的分工是否有共识？

## `canvas_fields` 必填

| 字段 | 内容 |
|---|---|
| `hmw` | 基于核心问题形成的 HMW |
| `loop_goal` | MVL 核心目标 |
| `capability_metrics` | 核心能力指标 |
| `acceptance` | 验收判定标准 |
| `boundary` | 能力和功能边界 |
| `solution_direction` | 已锁定的 AI 方案方向及理由 |
| `workflow_draft` | 触发、步骤、完成条件、三类节点和关键规则；结构见唯一映射中的“AI 工作流结构契约” |
| `validation_dimensions` | 分层验证维度 |

## 放行检查

- [ ] HMW 来自 M2 已确认问题，没有预设未经讨论的答案。
- [ ] 闭环有明确触发和完成条件。
- [ ] 指标与验收标准可判定。
- [ ] 工作流体现 AI 应用，而不是只复述现状业务流程。
- [ ] 自动化节点（Agent 执行）、人工操作/确认节点、人审 + Agent 执行节点和关键规则均已明确。
- [ ] 方案方向、边界和验证维度已确认。
- [ ] 业务方和技术方对"闭环边界"和"人机分工"的理解已对齐，或分歧已显式记录。
