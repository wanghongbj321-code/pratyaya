# M2：需求发现、用户与真实流程拆解

> Canvas 贡献：User——用户 / 需求 / 痛点 / 最重要的结果；为 Workflow 提供现状流程
> 内容边界：`../references/workshop-canvas-map.md`

## 本模块必须完成

1. 明确目标用户、核心诉求、使用场景与行为链路。
2. 梳理真实业务流程和痛点。
3. 找出 AI 可优化切入点。
4. 区分 AI 刚需和增值需求，完成归档与优先级排序。
5. 明确每类关键用户最重要的结果。

## 引导问题

1. 谁实际参与或使用这个流程？各自要完成什么任务？
2. 最近一次真实业务从开始到结束怎样流转？
3. 用户在哪些环节等待、返工、出错或承担风险？
4. 用户的核心诉求和最重要结果是什么？
5. 哪些痛点必须由本次 MVL 覆盖？
6. 哪些需求是 AI 刚需，哪些只是增值？优先级依据是什么？
7. 【对齐检查】业务方和技术方对"用户"的定义是否一致？对"最重要结果"的排序是否一致？

用户数量和分类以实际讨论为准，不预设固定层数。

## `canvas_fields` 必填

| 字段 | 内容 |
|---|---|
| `users` | 用户与使用场景 |
| `needs` | 核心诉求与必须覆盖的需求 |
| `pain_points` | 有证据的流程痛点 |
| `most_important_outcomes` | 各关键用户最重要的结果 |
| `current_workflow` | 真实现状流程与行为链路 |
| `requirements` | 刚需/增值、优先级及依据 |

## 放行检查

- [ ] 用户、需求、痛点和最重要结果均有讨论依据。
- [ ] 现状流程来自真实案例，不是理想流程。
- [ ] 痛点能定位到具体流程环节。
- [ ] AI 刚需与增值需求已区分并排序。
- [ ] 业务方和技术方对"用户"和"最重要结果"的定义已对齐，或分歧已显式记录。
