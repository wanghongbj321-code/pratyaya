# M2 框架：用户画像与真实流程拆解（D1 下午 14:00–17:30）

> 对应日程：AI场景需求发现、用户与真实流程拆解。
> MAAU 落点：**User（用户）** 板块 —— 用户 / 需求 / 痛点 / 最重要的结果；现状流程素材（为 Workflow 供料）。
> 方法来源：`references/methods/07-case-card-baseline.md`、`references/methods/08-user-persona.md`、`references/methods/09-user-journey.md`、`references/methods/14-insight-four-steps.md`。信条：先理解，后解决；先用户，后技术。

## 讨论支架（引导师用）

| 环节 | 时间盒 | 产出 |
|------|--------|------|
| 案例与基线：Owner 讲最近 1 个真实案例，填案例卡五格 | 20 min | 案例卡+基线 |
| User Persona：三层用户（直接/受益者/决策者），五字段 | 40 min | Persona ×3 |
| Current Journey：七要素画用户真正走的路 | 60 min | 旅程图 |
| 洞察提炼：事实→张力→原因→机会 | 30 min | 洞察卡 3-5 条 |
| 需求收敛：区分 AI 刚需 vs 增值，排优先级 | 40 min | 需求清单 |

## 引导问题清单

1. 案例卡：最近一次真实业务怎么走的？（背景·输入·处理过程·输出·结果，五格不留空）
2. 基线四指标：周期多长？人工耗时多少？返工几次？出错/退回率多少？（哪怕粗，必须有数字）
3. 三层用户：谁直接操作？谁拿到价值？谁拍板担责？各自的五字段（目标·典型行为·痛点·决策因素·影响力）？
4. Current Journey：端到端走一遍——行动·触点·系统·情绪曲线·等待·返工·风险节点，标出来
5. 情绪最低点在哪？等谁？等多久？返工主因是什么？
6. 洞察卡：观察到什么事实？它和什么冲突（张力）？为什么（原因）？所以我们可以……（机会）
7. 需求分级：哪些是 AI 刚需（不做就痛），哪些是增值（有了更好）？排序依据？

## 提取字段

| 字段 | 说明 | 必填 |
|------|------|------|
| caseCard | 案例卡五格：背景/输入/处理过程/输出/结果 | 是 |
| baseline[] | 基线四指标：周期/人工耗时/返工次数/出错退回率 | 是 |
| personas[] | 三层用户：层级/目标/典型行为/痛点/决策因素/影响力/最重要的结果 | 是 |
| journey[] | Current Journey：阶段/行动/触点/系统/情绪/等待/返工/风险 | 是 |
| insights[] | 洞察卡：事实/张力/原因/机会 | 是，≥3 条 |
| requirements[] | 需求：描述/刚需或增值/优先级/依据 | 是 |

## 输出模板（module-2.md）

```markdown
# 模块2：用户画像与真实流程拆解

## 案例卡与基线四指标
## 三层用户画像（直接用户 / 受益者 / 决策者）
| 用户 | 层级 | 目标 | 典型行为 | 痛点 | 决策因素 | 最重要的结果 |
## Current Journey（七要素）
| 阶段 | 行动 | 触点 | 系统 | 情绪 | 等待 | 返工 | 风险节点 |
## 洞察卡（事实→张力→原因→机会）
## 需求清单（刚需 / 增值 + 优先级依据）
## 争议与悬而未决（Parking Lot）
## 〔推断〕待确认项
## 缺口与补问清单
```

## 质量检查清单（及格线）

- [ ] 基线四指标全部有数字（哪怕粗）
- [ ] Journey 上至少标出 2 个等待、1 个返工、1 个风险节点
- [ ] 每条洞察经得起「事实—张力—原因—机会」四步追问
- [ ] 每条用户行为有案例出处（严禁「用户应该」）
- [ ] 三层用户齐全，各有「最重要的结果」一句话

## 陷阱（引导时提醒小组）

用组织图代替用户旅程 / 用「用户应该」代替「用户实际」 / 把系统边界当流程终点（画到业务结果产生为止）/ 急着下结论。「工作坊里最贵的四个字：我觉得是。」
