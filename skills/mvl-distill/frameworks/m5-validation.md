# M5：三轮验证、交互优化与信任控制校验

> Canvas 贡献：Validation——能否执行 / 能否创造价值；信任与风险控制
> 内容边界：`../references/workshop-canvas-map.md`

## 本模块必须完成

1. 第一轮验证核心自治流程可用性。
2. 第二轮优化智能交互体验并适配用户使用习惯。
3. 第三轮校验信任机制和风险控制机制。
4. 记录每轮验证的方法、发现、修改和结果。
5. 汇总闭环漏洞及整改状态。

## 引导问题

1. 第一轮：核心自治流程是否跑通？证据、问题和修改是什么？
2. 第二轮：交互在哪些地方不适配用户习惯？修改前后有什么变化？
3. 第三轮：需要校验哪些信任和风险控制机制？结果是否稳定、合理？
4. 三轮中分别发现了哪些闭环漏洞？
5. 哪些问题已经整改，哪些仍然遗留？
6. 对照成功指标，当前实测结果是否达到目标？
7. 现有流程、数据、人机分工和控制机制是否足以执行？
8. 【对齐检查】业务方和技术方对"验证通过标准"的理解是否一致？对"风险可控"的阈值是否有共识？

验证场景和风险分类以现场讨论为准，不强制预设固定攻击类型。

## `canvas_fields` 必填

| 字段 | 内容 |
|---|---|
| `validation_rounds` | 三轮验证：目标 / 方法 / 发现 / 修改 / 结果 |
| `can_execute` | 能否执行的结论与证据 |
| `can_create_value` | 指标 / 目标 / 实测 / 衡量方式 / 达成情况 |
| `trust_risk_controls` | 信任机制、风险控制、结果和责任角色 |
| `issues_corrections` | 问题 / 整改动作 / 状态 |

## 放行检查

- [ ] 三轮验证与正式日程的三个目标一一对应。
- [ ] 每轮都有验证证据、发现、修改和结果。
- [ ] 能否执行和能否创造价值均有证据。
- [ ] 信任与风险控制结论来自实际校验。
- [ ] 遗留问题显式记录。
- [ ] 业务方和技术方对"验证通过标准"和"风险可控阈值"的理解已对齐，或分歧已显式记录。
