# M5 框架：三轮验证与信任控制（D3 上午 09:00–12:00）

> 对应日程：MVL闭环三轮验证、交互优化与信任控制机制闭环校验。
> MAAU 落点：**Validation（闭环验证）** —— 1.能否执行 2.能否创造价值 3.信任与风控机制。
> 方法来源：`references/methods/11-red-team.md`、`references/methods/09-user-journey.md`（Future Journey 部分）。核心认知：失败模式都是**沉默的**——不报警，只在事后变事故。

## 引导问题清单

1. Round 1：核心自治流程跑通了吗？卡在哪？证据是什么（跑了几轮/成功率/耗时）？
2. Round 2：针对用户习惯改了什么？改前改后对比？
3. Round 3 红队六类攻击，逐类过：
   - 信息缺失：删掉两个关键字段再提交，报告会不会照出不误？
   - 数据冲突：喂入与主数据矛盾的信息，能识别口径不一吗？
   - 越权访问：低权限账号调取涉密内容，拦得住吗、有留痕吗？
   - 幻觉编造：问不存在的法条/案例，拒答还是编造？
   - 业务误导：诱导 Agent 越界承诺，守得住决策边界吗？
   - 异常吞没：低置信度结果显式上报，还是悄悄通过？
4. 三方视角：用户（结果可信吗·顺手吗）/ 业务（快了吗·顺吗）/ IT（权限·日志·脱敏·审计达标吗）？
5. 发现哪些闭环漏洞？每个怎么补的（或遗留）？
6. 对照 M1 成功指标：实测数字多少？达成/未达成？
7. Future Journey：嵌入 MVL 后用户的一天变成什么样？每步 S 还是 C？

## 质量检查清单（及格线）

- [ ] 「能执行」「能创造价值」每个结论挂验证证据，不接受无证据结论

- [ ] 每个风险点有明确兜底人（角色，不是「大家」）
- [ ] 遗留问题显式列出，不许悄悄带入下一阶段
