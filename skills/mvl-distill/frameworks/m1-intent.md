# M1 框架：战略对齐与核心价值（D1 上午 09:00–12:00）

> 对应日程：AI原生战略对齐、项目分组与MVL闭环证据准备。
> MAAU 落点：**Intent（意图）** 板块 —— 目标 Goal / 价值 Value / 成功指标 Success Metrics + 校验标准与边界。
> 方法来源：`references/methods/00-global-framework.md`、`references/methods/03-collaboration-rules.md`、`references/methods/04-five-dimension-diagnosis.md`、`references/methods/06-weighted-scoring.md`、`references/methods/01-evidence-pack.md`。

## 讨论支架（引导师用）

| 环节 | 时间盒 | 产出 |
|------|--------|------|
| 开场与协作规则五条 | 20 min | 约定上墙 |
| 证据对齐：现有流程痛点、业务数据、真实案例（Evidence Pack 过堂） | 40 min | 证据墙 |
| North Star 校准：Why（战略牵引）→ How（AI 原生 ≠ 买软件+装插件）→ What（12 个月成功画像） | 60 min | 成功画像 |
| 场景/方向确认：五维评分（价值30%·频率20%·数据20%·规则15%·风险15%）→ 锁定范围与 Owner | 50 min | 评分表+Owner |
| 校验标准与边界：本次闭环"做什么、不做什么、怎么算成" | 30 min | 校验标准 |

## 引导问题清单

1. 这个 AI 场景解决的核心业务问题是什么？不解决会怎样？（锚定真实案例与数据）
2. 12 个月后，什么样算「成了」？画出成功画像：谁的工作发生了什么变化？
3. 核心价值主张：为谁，把什么，从什么状态变成什么状态？
4. 证据墙：现有流程的最大痛点，证据是什么（数据/案例/投诉记录）？
5. 五维评分：这个场景的价值/频率/数据就绪度/规则明确度/失败代价，各打几分、理由？
6. 边界：本次 MVL 闭环明确**不做**什么？
7. 校验标准：什么叫"验证通过"？谁来判定？基线数字现在是多少？

## 提取字段

| 字段 | 说明 | 必填 |
|------|------|------|
| goal | 目标（业务结果导向，非功能清单） | 是 |
| value[] | 价值清单，每条标注受益者 | 是 |
| successMetrics[] | 成功指标（量化，含基线→目标值） | 是 |
| northStar | 12 个月成功画像 | 是 |
| scoring[] | 五维评分：维度 / 得分 / 理由 | 是 |
| evidence[] | 证据清单（数据/案例/流程文档） | 是 |
| boundary | 边界范围（做 / 不做） | 是 |
| acceptance | 校验标准与判定人 | 是 |
| roles[] | 分组与角色卡（Owner/主持记录/一线用户/业务方/技术数据） | 有则提取 |

## 输出模板（module-1.md）

```markdown
# 模块1：战略对齐与核心价值

## 目标（Goal）
## 价值清单（Value，标注受益者）
## 成功指标（Success Metrics：指标 / 基线 / 目标值）
## 12个月成功画像（North Star）
## 五维评分表（价值30/频率20/数据20/规则15/风险15）
## 证据清单（Evidence Pack）
## 校验标准与边界范围（含"不做什么"）
## 分组与角色卡
## 争议与悬而未决（Parking Lot）
## 〔推断〕待确认项
## 缺口与补问清单
```

## 质量检查清单（及格线）

- [ ] 成功指标全部量化且有基线（「提升效率」一律打回：提升什么、从几到几）
- [ ] 每条价值能对应一类受益者（直接用户/受益者/决策者）
- [ ] 五维评分每项有分数+理由，缺理由进缺口清单
- [ ] 边界写出至少 1 条「不做」
- [ ] 校验标准可判定（是/否能验，而非「体验良好」）
