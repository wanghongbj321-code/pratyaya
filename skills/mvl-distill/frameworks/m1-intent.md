# M1：战略对齐、项目分组与闭环证据准备

> Canvas 贡献：Intent——目标 / 价值 / 成功指标
> 内容边界：`../references/workshop-canvas-map.md`

## 本模块必须完成

1. 对齐 AI 场景的核心业务目标与价值。
2. 完成项目分组，明确参与角色。
3. 汇总业务数据、用户案例、现有流程痛点等核心证据。
4. 明确本次 MVL 的成功指标、核心校验标准和边界范围。

## 引导问题

1. 这个场景要解决的核心业务问题是什么？不解决会造成什么影响？
2. 价值体现在哪里，谁会获得价值？
3. 现有业务数据、用户案例和流程痛点分别提供了什么证据？
4. 用哪些成功指标判断有效？现状基线、目标值和衡量方式是什么？
5. 本次 MVL 做到哪里为止，明确不包含什么？
6. 谁负责业务判断、讨论记录、技术/数据支持和用户反馈？
7. 【对齐检查】业务方定义的"成功"和技术方理解的"可实现目标"是否一致？如果有差异，差异在哪里？

## `canvas_fields` 必填

| 字段 | 内容 |
|---|---|
| `goal` | 核心业务目标 |
| `value` | 价值及受益对象 |
| `success_metrics` | 指标 / 基线 / 目标 / 衡量方式 |
| `evidence` | 业务数据 / 用户案例 / 流程痛点等证据 |
| `boundary` | 边界范围 |
| `acceptance` | 核心校验标准与判定方式 |
| `grouping` | 项目分组与参与角色 |


## 放行检查

- [ ] 目标是业务结果，不是功能名称。
- [ ] 价值对象明确。
- [ ] 成功指标包含基线、目标和衡量方式。
- [ ] 每类核心证据可回到来源。
- [ ] 校验标准可判定，边界可说明。
- [ ] 项目分组已记录。
- [ ] 业务方和技术方对"成功"的理解已对齐，或分歧已显式记录。
