# User Persona（三层用户）

> 用途：M2 模块，识别 MVL 服务的所有利益相关者。

## 三层用户

一个 MVL 的用户不只是"直接操作者"，至少有三层：

| 层级 | 定义 | 示例 |
|------|------|------|
| 直接用户 | 直接使用 MVL 的人 | 一线操作员 |
| 受益者 | 因 MVL 产出而受益的人 | 业务负责人 |
| 决策者 | 对 MVL 的存废有拍板权的人 | 部门总监 |

**铁律**：三层用户一个都不能少。只服务直接用户，会忽略受益者和决策者的诉求。

## Persona 五字段

每层用户至少做 1 个 Persona，每个 Persona 填写 5 个字段：

| 字段 | 问题 | 要求 |
|------|------|------|
| 目标 | 这个用户想要达成什么？ | 具体、可衡量 |
| 典型行为 | 他通常怎么做？ | 基于真实观察，不是"应该" |
| 痛点 | 他遇到的最大困难是什么？ | 用他的原话 |
| 决策因素 | 他做判断时最看重什么？ | 效率？成本？风险？ |
| 影响力 | 他对 MVL 的存废有多大影响力？ | 高/中/低 |

## 导师话术

- "三层用户：谁用、谁受益、谁拍板。漏一层，MVL 就少一条腿。"
- "Persona 不是'用户应该怎么做'，是'用户实际怎么做'。每条行为必须有案例出处。"
- "痛点要用用户的原话，不要用你的总结。"

## 陷阱与解药

**陷阱**：用组织图代替用户画像（"这个岗位负责这个"）  
**解药**：追问"他实际上是怎么做的？有没有例外？"

**陷阱**：用"用户应该"代替"用户实际"  
**解药**：每条行为追问"你亲眼见过吗？有案例吗？"

**陷阱**：只做了直接用户，没做受益者和决策者  
**解药**：强制检查三层是否齐全

**陷阱**：Persona 字段空着不填  
**解药**：空着就说明你没研究透，现场补

## 及格线

- 三层用户至少各有 1 个 Persona
- 每个 Persona 五字段至少填了 3 个
- 行为描述有案例出处（不是"应该"）
