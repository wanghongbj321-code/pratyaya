# 全局方法论框架

> 用途：闭环助教的底层方法论，贯穿 M1~M6 所有模块。

## 五件兵器（全组共同语言）

1. **User Persona**：三层用户——直接用户 / 受益者 / 决策者，一个都不能少
2. **User Journey**：Current（真实走的路）→ Future（MVL 嵌入后的路）
3. **HMW**：把痛点改写成「我们如何能……」的可激发问题
4. **MVL Canvas**：六字段（Intent · User · Agent Team · Workflow · Context · Validation）
5. **纸面原型**：打印界面卡 + 主持人后台「扮演 Agent」，一天可三轮

> 导师原则：模板是脚手架，不是笼子——先用熟，后破。

## 三明治工作流（人机分工总纲）

- **Silicon 执行层（Agent 做）**：检索 · 比对 · 初稿 · 标签 · 召回——可错但快
- **Carbon 复核层（人做）**：抽样复核 · 例外裁决 · 风险确认——质量阀
- **Carbon 决策层（人做）**：拍板、担责

→ 提炼 Agent Team 时，每个角色的「决策边界」按 S/C 层标注。

## 协作规则五条

① 真实优先（锚定真实案例与数据）  
② 车位留给业务（业务发言不打断，术语当场翻译）  
③ 原型思维（不争论"能不能"，只做"试试看"）  
④ 时间盒神圣（到点即停，未完成进停车场）  
⑤ Parking Lot（悬而未决全部上墙留痕）

## 角色卡（每组六类）

场景 Owner（拍板权，对成败负责）/ 主持·记录员（守时间盒、留痕版本）/ 一线用户 ×2-3（真实操作者，原型测试主角）/ 业务方（提需求、给约束、判价值）/ 技术·数据代表（判数据就绪度与系统边界）/ 导师（巡回提问不代答）

## 五维诊断框架（前期问卷解读用）

- **People**（GWC：Goal-Will-Capability）
- **Process**（全链路断点、三明治适配点）
- **Data**（数据资产、机器可读性、分级治理）
- **Issue**（高频痛点）
- **Traction**（牵引力/变革准备度）

## 加权评分模型（选场景 & 排优先级，同一把尺）

| 维度 | 权重 | 评估内容 |
|------|------|----------|
| 价值 | 30% | 业务影响面 |
| 频率 | 20% | 发生频次 |
| 数据 | 20% | 数据就绪度 |
| 规则 | 15% | 规则明确度 |
| 风险 | 15% | 失败代价可控性 |

## 总节奏（2+5+7+28）

2 天前期诊断（问卷）→ 现场共创（本次 3 天）→ 后续真实验证 → 7 天资产沉淀 → 28 天运营节奏规模化。

本次工作坊只交付**模拟环境概念验证原型**，不是生产系统。
