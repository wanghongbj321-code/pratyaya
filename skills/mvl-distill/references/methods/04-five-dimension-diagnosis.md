# 五维诊断框架

> 用途：M1 前期问卷解读、场景筛选的底层逻辑。

## 五维框架

### 1. People（人）

评估维度：**GWC（Goal-Will-Capability）**

- **Goal（目标清晰吗）**：团队知道要解决什么问题吗？目标可衡量吗？
- **Will（意愿强烈吗）**：团队愿意为改变付出代价吗？还是只是"想看看"？
- **Capability（能力够吗）**：团队有执行所需的技能、资源、权限吗？

**诊断信号**：
- 目标模糊 → 需要先对齐战略意图
- 意愿不足 → 需要先建立信任和价值感
- 能力缺失 → 需要先补资源或调整范围

### 2. Process（流程）

评估维度：**全链路断点、三明治适配点**

- 端到端流程画出来了吗？
- 哪些节点有断点（等待、返工、信息丢失）？
- 哪些节点适合 Agent 执行（Silicon）？哪些必须人判断（Carbon）？

**诊断信号**：
- 流程没画出来 → 团队对业务理解不统一
- 断点太多 → 先选 1-2 个高价值断点做 MVL
- 人机分工不清 → 先做三明治分层

### 3. Data（数据）

评估维度：**数据资产、机器可读性、分级治理**

- 有哪些数据资产？（文档、记录、日志、知识库）
- 数据机器可读吗？（结构化 vs 非结构化、干净 vs 脏）
- 数据分级治理做了吗？（公开 / 内部 / 敏感 / 机密）

**诊断信号**：
- 数据不可得 → MVL 范围要调整，先做数据治理
- 数据脏乱 → 先做数据清洗，再上 Agent
- 数据没分级 → 先做权限管控，否则上线即失控

### 4. Issue（痛点）

评估维度：**高频痛点**

- 一线用户最常抱怨什么？
- 哪些痛点重复出现、影响面广？
- 哪些痛点有明确的数据支撑？

**诊断信号**：
- 痛点笼统 → 需要先做用户调研和案例收集
- 痛点与管理层认知脱节 → 需要一线用户直接参与
- 痛点无数据支撑 → 需要先建基线

### 5. Traction（牵引力）

评估维度：**牵引力 / 变革准备度**

- 团队愿意尝试新方法吗？
- 有成功案例可以借鉴吗？
- 有内部 champion 推动吗？

**诊断信号**：
- 牵引力弱 → 需要先做小规模试点，建立信心
- 牵引力强 → 可以直接做全流程 MVL

## 使用场景

- **M1 前期**：解读问卷数据，识别团队短板
- **M1 场景筛选**：用五维评估每个候选场景
- **M6 优先级排序**：用五维评估每个 MVL 的可行性

## 及格线

- 每个维度至少有 1 条诊断结论
- 识别出至少 1 个短板（People/Process/Data/Issue/Traction）
- 短板有对应的解药（不是空话）
