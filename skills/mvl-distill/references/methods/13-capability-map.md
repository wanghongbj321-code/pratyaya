# 跨场景能力地图

> 用途：M6 模块，识别多个 MVL 之间的共用资产，避免重复建设。

## 六类共用资产

把各组 MVL Canvas 的 Context 和 Workflow 拆开平铺，识别六类共用资产：

| 类型 | 定义 | 示例 |
|------|------|------|
| 共用知识 | 多个 MVL 都需要用的知识库 | 法规库、案例库、术语表 |
| 共用数据 | 多个 MVL 都需要用的数据源 | 客户主数据、合同库、财务数据 |
| 共用工具 | 多个 MVL 都需要用的工具 | 文档解析、OCR、签名服务 |
| 共用流程 | 多个 MVL 都需要用的流程节点 | 审批流程、通知流程、归档流程 |
| 共用评测 | 多个 MVL 都需要用的评测方法 | 评测数据集、评测指标、评测流程 |
| 共用治理 | 多个 MVL 都需要用的治理机制 | 权限管理、日志审计、数据脱敏 |

## 就绪度标注

每类共用资产标注就绪度：

- ● **今天就有**：已经存在，可以直接用
- ◐ **需要建设**：部分存在，需要补充或改造
- ○ **盲区**：完全没有，需要从零建设

| 共用资产 | MVL-1 | MVL-2 | MVL-3 | 就绪度 |
|----------|-------|-------|-------|--------|

## 导师话术

- "不要造 N 个独立的 MVL，要造一个 MVL 网络。"
- "共用资产是杠杆：建设一次，多个 MVL 受益。"
- "就绪度标注：● 今天就有、◐ 需要建设、○ 盲区。先做●，再做◐，最后做○。"

## 陷阱与解药

**陷阱**：各组 MVL 独立建设，重复造轮子  
**解药**：先画能力地图，识别共用资产，再分工建设

**陷阱**：共用资产就绪度标注不准确（"应该有"）  
**解药**：现场验证，翻系统、查文档、问技术人员

**陷阱**：能力地图太粗（"知识管理"）  
**解药**：拆细，拆到具体的知识库、数据源、工具

## 及格线

- 六类共用资产全部识别
- 每个 MVL 的依赖关系标注清楚
- 就绪度标注准确（有证据支撑）
- 识别出至少 2 个高价值共用资产
