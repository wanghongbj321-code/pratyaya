# 三明治工作流（人机分工总纲）

> 用途：M4 Agent Team 设计的底层逻辑，贯穿全流程。

## 三层分工

### Silicon 执行层（Agent 做）

**特征**：可错但快，可并行，可规模化

**典型任务**：
- 检索（从知识库、数据库、文档库找信息）
- 比对（对比两份文档、两个数据源）
- 初稿（生成报告、邮件、方案草稿）
- 标签（分类、打标、提取关键词）
- 召回（从历史记录中找相似案例）

**设计原则**：
- 允许一定错误率（< 10%）
- 速度快（秒级响应）
- 可并行处理（批量任务）

### Carbon 复核层（人做）

**特征**：质量阀，例外裁决，风险确认

**典型任务**：
- 抽样复核（随机抽查 Agent 输出）
- 例外裁决（Agent 无法处理的案例）
- 风险确认（高风险决策前的人工把关）
- 异常上报（低置信度结果的显式处理）

**设计原则**：
- 抽样比例可调整（初期 100%，稳定后 10%）
- 例外裁决要有记录（形成知识库）
- 风险确认要有标准（不是凭感觉）

### Carbon 决策层（人做）

**特征**：拍板、担责

**典型任务**：
- 最终决策（签合同、批预算、发公告）
- 责任承担（出了问题谁负责）
- 价值判断（这件事值不值得做）

**设计原则**：
- 决策权不能下放给 Agent
- 决策过程要有记录（为什么选 A 不选 B）
- 决策结果要可追溯

## 在 Agent Team 设计中的应用

**每个角色的「决策边界」按三层标注**：

| 角色 | Silicon 执行 | Carbon 复核 | Carbon 决策 |
|------|-------------|-------------|-------------|
| 合同审查 Agent | 初稿生成、条款比对 | 例外条款人工复核 | 最终签约权在人 |
| 风险评估 Agent | 数据收集、初步评分 | 高风险案例人工确认 | 是否接受风险在人 |
| 报告生成 Agent | 数据提取、报告初稿 | 关键数据人工核验 | 报告发布权在人 |

## 陷阱与解药

**陷阱**：把 Agent 设计成万能 Agent（什么都能做）  
**解药**：每个角色只负责一层，跨层必须有交接点

**陷阱**：Carbon 复核层太厚（所有输出都要人工复核）  
**解药**：根据 Agent 置信度动态调整复核比例

**陷阱**：Carbon 决策层模糊（不知道谁拍板）  
**解药**：每个流程节点明确标注决策人（RACI 矩阵）

## 导师话术

- "Agent 不是替代人，是帮人做重复性的累活。人负责判断和决策。"
- "三明治的核心是：Agent 可错但快，人复核但慢。快慢结合，效率和质量都要。"
- "决策权永远在人。Agent 可以建议，但不能拍板。"
