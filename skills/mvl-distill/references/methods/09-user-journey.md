# User Journey（七要素）

> 用途：M2 模块，画出用户当前真实走的流程，识别断点和机会。

## Current Journey 七要素

端到端画出用户真实走的路，每个阶段标注七个要素：

| 要素 | 问题 | 标注方式 |
|------|------|----------|
| 行动 | 用户在这步做了什么？ | 动词短语 |
| 触点 | 用户和谁/什么交互？ | 人/系统/文档 |
| 系统 | 用了什么系统？ | 系统名称 |
| 情绪 | 用户感受如何？ | 😊 😐 😡（高/中/低） |
| 等待 | 等了多久？ | 时间（分钟/小时/天） |
| 返工 | 有没有返工？为什么？ | 返工原因 |
| 风险节点 | 哪里可能出错？ | 风险描述 |

## 画 Journey 的步骤

1. **定起点和终点**：从"收到任务"到"交付结果"
2. **拆阶段**：按用户行动拆成 3-7 个阶段
3. **填七要素**：每个阶段逐格填写
4. **标情绪曲线**：画出用户情绪的高低起伏
5. **找断点**：等待最长、返工最多、风险最大的节点

## Future Journey（M5 模块用）

在 Current Journey 基础上，标注每个阶段：
- **S（Silicon 执行）**：Agent 可以做
- **C（Carbon 判断）**：必须人做

对比 Current 和 Future，识别：
- 哪些阶段可以自动化？
- 哪些阶段必须保留人工？
- 哪些阶段需要人机协作？

## 导师话术

- "画用户真正走的路，不是画组织图上的流程。"
- "等待和返工是金矿——等待越长、返工越多，MVL 的价值越大。"
- "情绪曲线是用户的真实感受，不是你觉得他应该有的感受。"

## 陷阱与解药

**陷阱**：把系统边界当流程终点（画到"系统处理完"就停了）  
**解药**：画到业务结果产生为止（用户拿到结果才算完）

**陷阱**：用组织图代替用户旅程（"这个部门负责这个"）  
**解药**：用用户的视角画，不是用组织的视角

**陷阱**：急着下结论（"这里应该用 AI"）  
**解药**：先画完，再讨论。画的过程中不要讨论解决方案

## 及格线

- Journey 至少拆成 3 个阶段
- 每个阶段至少标注了 3 个要素
- Journey 上至少标出 2 个等待、1 个返工、1 个风险节点
- 情绪曲线有高低起伏（不是全程 😐）
