# SWOT/TOWS 模块规范

本文件是 `swot-distill` 和 `swot-gate` 共用的事实源定义。固化 SWOT Key Points 与确认包的固定 section、ID 约定与 Canvas 映射。

## SWOT Key Points 固定结构

参见 `swot-distill/SKILL.md` 的 Stage 1 模板。必含 section：

1. 课题卡概览（分析主体、决策问题与目标、业务边界、时间范围、比较基准、可控边界、已知约束、关键假设与分歧）
2. 材料整理摘要（用户提供的关键材料、数据与背景）
3. SWOT 因素候选（按 S/W/O/T 初步分组，含待分类候选）
4. 因素质量初判（证据强度、分类确定性、重要性与处理建议）
5. TOWS 策略线索（初步推导的 SO/ST/WO/WT 策略候选）
6. 覆盖度初判（课题卡、四象限、TOWS 四组的覆盖情况）
7. 用户决策提示（提炼 / 补问 / 先看个样子）

## SWOT 确认包固定 section

确认包 `SWOT-{slug}-v{N}.md` 的必填 section（写入业务内容，名称固定，共 12 节）：

| 节号 | section 名称 | 内容 |
|---|---|---|
| 1 | 必展项（紧凑前置） | 一句话结论、对齐摘要、阻塞项、缺口速览、待确认版本 |
| 2 | 课题卡 | 分析主体、决策问题与目标、业务边界、时间范围、比较基准、可控边界、已知约束、关键假设与分歧 |
| 3 | SWOT 四象限 | S/W/O/T 各象限因素列表，每条含 6 字段分组（身份与分类、判断性质、内容来源、证据与局限、对决策的影响、重要性与处理） |
| 4 | 待分类候选 | 归属未明的因素，保留候选身份，不作为分类已成立的 TOWS 依据 |
| 5 | 被排除因素 | 被排除的因素及排除原因，便于追查策略依据 |
| 6 | TOWS 策略 | SO/ST/WO/WT 四组策略，每条含 6 字段（策略身份、推导依据、成立条件、代价与风险、比较与取舍、验证与复审） |
| 7 | 选项比较与取舍 | 比较的选项、AI 推荐、用户当前决定及理由；保留其他比较选项 |
| 8 | 最小交接与复审 | 下一步事项、承接角色/人、约定时间或触发条件、预期交付物与判断标准 |
| 9 | 结论登记表 | ID（SWOT-Cxx）/ 结论 / 类型 / 共识状态 |
| 10 | 缺口表 | ID（SWOT-Gxx）/ 等级 / 状态 / 描述 / 缺失影响 / 最少补问 |
| 11 | 证据与推断登记 | 原材料位置、事实/判断/假设分层、推断及影响；用户认可不改变证据性质 |
| 12 | Gate 与用户决策 | Gate 建议、用户授权与 override 审计（治理元数据） |

section 没有讨论到时，不得补写。将它标为缺口并说明对本次 SWOT 产出和最终 Canvas 的影响。

## ID 约定

| 前缀 | 含义 | 示例 |
|---|---|---|
| `S-` | 优势因素（Strength） | `SWOT-F-S01`：核心优势第 1 条 |
| `W-` | 劣势因素（Weakness） | `SWOT-F-W01`：核心劣势第 1 条 |
| `O-` | 机会因素（Opportunity） | `SWOT-F-O01`：外部机会第 1 条 |
| `T-` | 威胁因素（Threat） | `SWOT-F-T01`：外部威胁第 1 条 |
| `CAND-` | 待分类候选 | `CAND-01`：归属未明的第 1 条 |
| `EXCL-` | 被排除因素 | `EXCL-01`：被排除的第 1 条 |
| `SWOT-STR-` | TOWS 策略 | `SWOT-STR-SO01`：SO 策略第 1 条 |
| `SWOT-C` | 结论（Conclusion） | `SWOT-C01`：SWOT 关键结论 |
| `SWOT-G` | 缺口（Gap） | `SWOT-G01`：SWOT 缺口 |
| `SWOT-INF-` | 推断（Inference） | `SWOT-INF-01`：SWOT 推断 |

> **注意**：因素编号不随象限调整而改变。被排除因素保留 EXCL- 前缀和排除原因。推断 ID 用 `SWOT-INF-NN`，避免与因素编号混淆。

## 因素字段要求

第 3 节（SWOT 四象限）的每条因素必须包含以下 6 字段分组：

| 字段分组 | 必填 | 说明 |
|---|---|---|
| 身份与分类 | 是 | 稳定编号（SWOT-F-S01/SWOT-F-W01/SWOT-F-O01/SWOT-F-T01）、具体陈述、S/W/O/T 分类 |
| 判断性质 | 是 | 事实陈述 / 判断 / 假设；依据材料作出的解释写清推导过程 |
| 内容来源 | 是 | 用户材料 / 用户补充 / AI 推导，并记录来源位置或所依据的因素 |
| 证据与局限 | 是 | 支持材料、材料类型、日期及适用范围；缺失项、反证和冲突明确记录 |
| 对决策的影响 | 是 | 如何影响目标、在什么条件下成立、相对什么基准判断 |
| 重要性与处理 | 是 | 高/中/低及理由；保留/待验证/排除，并说明原因 |

> 来源不等于证明。原材料位置只记录“在哪里提出”，不能升级证据性质。事实、判断、假设必须分开；用户认可只能确认其作为当前工作假设/决策输入，不能把判断或假设升级为事实。

## TOWS 策略字段要求

第 6 节（TOWS 策略）的每条策略必须包含以下 6 字段：

| 字段 | 必填 | 说明 |
|---|---|---|
| 策略身份 | 是 | 稳定编号（SWOT-STR-SO01/SWOT-STR-ST01/SWOT-STR-WO01/SWOT-STR-WT01）、名称、SO/ST/WO/WT 类型 |
| 推导依据 | 是 | 关联因素编号、具体动作、预期作用机制 |
| 成立条件 | 是 | 关键假设、资源和能力要求、外部依赖 |
| 代价与风险 | 是 | 付出什么、可能损失什么、放弃了什么 |
| 比较与取舍 | 是 | 与哪些选项比较、AI 推荐、用户当前决定及理由 |
| 验证与复审 | 是 | 如何验证，什么结果或环境变化触发调整、暂停或重审 |

> TOWS 策略必须关联具体因素编号，写明作用机制与成立条件。假设沿推导链保留；关联编号本身不能证明策略可行。

## 缺口等级定义

| 等级 | 影响 | 处置 |
|---|---|---|
| `blocker` | 使画布核心产出（课题卡、因素分类、策略推导）无法成立 | 必须关闭，不允许接受风险 |
| `major` | 会显著改变态势分析或策略方向 | 必须关闭或接受风险 |
| `minor` | 不改变核心结论 | 可后续补齐或明确接受风险 |

## 不得自动引入

- 不得强制固定因素数量（每象限 3–5 条仅作篇幅建议，允许空象限并说明原因）。
- 不得把行动方案直接当作机会。
- 不得强行各出一类 TOWS 策略；无可靠策略时说明原因。
- 不得用加权总分替代 Gate 判断。
- 不得把用户采纳的假设变成已验证事实。
- 不得主动联网做外部战略研究。
- 不得自动向其他画布写入 SWOT 结论。
- 不得因为模板有四象限而补写没有讨论过的因素。
- 不得把"提高效率""降低成本"扩写为日程没有讨论的内容。
- 质量鉴别判定必须有转写证据线索，不得由 LLM 主观构造。
