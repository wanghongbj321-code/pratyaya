 # SWOT/TOWS 框架
 
 > 画布类型：SWOT/TOWS（态势分析与策略推导）画布
 > 理论来源：SWOT-TOWS 经典分析框架，结合 Pratyaya 项目的证据模型与 Gate 机制
 
 本文件由 `swot-distill` 在 Stage 1 和 Stage 2 时读取，是 SWOT 提炼的唯一内容边界。只采用课题卡、因素证据模型、TOWS 辅助推导、策略取舍与最小交接字段；不得把其他战略分析框架（VRIO、QSPM、AHP、PESTEL、五力等）自动变成必填 section；用户明确使用时按原话记录。
 
 ## 课题卡（8 字段，开始前确认核心边界）
 
 | 字段 | 含义 | 引导问题 |
 |---|---|---|
 | 分析主体 | 分析谁 | 本次 SWOT 分析的具体对象是什么？ |
 | 决策问题与目标 | 帮助谁做什么选择、希望达到什么 | 这份分析服务于什么决策？谁做决定？ |
 | 业务边界 | 涉及哪些业务、客户、市场或场景 | 分析覆盖哪些业务范围？不包含哪些？ |
 | 时间范围 | 判断在哪个期间成立 | 这些判断在什么时间段内有效？ |
 | 比较基准 | 相对什么判断优劣势 | 与谁或什么状态比较？（可待补） |
 | 可控边界 | 哪些是分析主体可控制的 | 哪些因素在主体控制范围内？ |
 | 已知约束 | 已知限制 | 有哪些已知的资源、政策或技术约束？ |
 | 关键假设与分歧 | 持续记录 | 有哪些尚未验证的关键假设或意见分歧？ |
 
 ## SWOT 因素（6 字段分组，每条因素）
 
 | 字段分组 | 记录内容 |
 |---|---|
 | 身份与分类 | 稳定编号（SWOT-F-S01/SWOT-F-W01/SWOT-F-O01/SWOT-F-T01 格式，编号不随象限调整改变）、具体陈述、S/W/O/T 分类；归属未明时保留为待分类候选 |
 | 判断性质 | 事实陈述 / 判断 / 假设；依据材料作出的解释写清推导过程 |
 | 内容来源 | 用户材料 / 用户补充 / AI 推导，并记录来源位置或所依据的因素 |
 | 证据与局限 | 支持材料、材料类型、日期及适用范围；缺失项、反证和冲突明确记录 |
 | 对决策的影响 | 如何影响目标、在什么条件下成立、相对什么基准判断 |
 | 重要性与处理 | 高/中/低及理由；保留/待验证/排除，并说明原因 |
 
 ## 分类规则
 
 | 规则 | 说明 |
 |---|---|
 | 以分析主体区分内外 | 同一现象对不同主体可能归属不同象限；不能只凭词语判断 |
 | 行动方案不是机会 | "建立分销网络"是行动，不是机会；真正的机会是外部条件 |
 | 双面影响拆分 | 同一现象的正负作用拆成不同条件下的因素，说明触发条件 |
 | 待分类候选 | 归属未明的因素保留为待分类候选，不强行分类 |
 
 ## TOWS 策略推导（6 字段，每条策略）
 
 | 字段 | 记录要求 |
 |---|---|
 | 策略身份 | 稳定编号、名称、SO/ST/WO/WT 类型 |
 | 推导依据 | 关联因素编号、具体动作、预期作用机制 |
 | 成立条件 | 关键假设、资源和能力要求、外部依赖 |
 | 代价与风险 | 付出什么、可能损失什么、放弃了什么 |
 | 比较与取舍 | 与哪些选项比较、AI 推荐、用户当前决定及理由 |
 | 验证与复审 | 如何验证，什么结果或环境变化触发调整、暂停或重审 |
 
 ## 最小交接（5 要素）
 
 | 要素 | 说明 |
 |---|---|
 | 关联策略或缺口 | 交接事项对应哪条策略或哪个已识别缺口 |
 | 下一步事项 | 具体要做什么 |
 | 承接角色/人 | 谁来承接（角色明确、姓名未知时标明） |
 | 约定时间或触发条件 | 什么时候完成或什么条件触发 |
 | 预期交付物与判断标准 | 交付什么、怎么判断完成 |
 
 ## 聚焦规则
 
 - 不强制填满四象限；允许空象限并说明原因
 - 每象限 3–5 条仅作篇幅建议，鼓励聚焦
 - 合并重复，解释双面影响；症状和原因保留关联
 - 编号不随象限调整而改变；被排除因素保留记录和原因
 
 ## 最低结论要求
 
 - 课题卡核心边界（分析主体、决策问题与目标、业务边界、时间范围）必须经用户确认
 - 因素分类必须基于分析主体，归属未明保留为待分类候选
 - TOWS 策略必须关联具体因素编号，写明作用机制与成立条件
 - 策略取舍必须区分 AI 推荐与用户决定
 - 最小交接只记录实际需要推进的事项
 
 ## 不得自动引入
 
 - 不得因为 SWOT 模板有四象限而补写没有讨论过的因素
 - 不得把行动方案直接当作机会
 - 不得强行各出一类 TOWS 策略；无可靠策略时说明原因
 - 不得用加权总分替代 Gate 判断
 - 不得把用户采纳的假设变成已验证事实
 - 不得主动联网做外部战略研究
 - 不得自动向其他画布写入 SWOT 结论
