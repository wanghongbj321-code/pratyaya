# HMW 框架

> 画布类型：How Might We（问题重构）画布
> 理论来源：HMW 改写三步法（源自 `skills/mvl-distill/references/methods/10-hmw.md`，MVL M3 子模块）

本文件由 `hmw-distill` 在 Stage 1 和 Stage 2 时读取，是 HMW 提炼的唯一内容边界。只采用陈述四字段、质量鉴别四维度与想法种子字段；不得把其他方法、术语或通用咨询框架自动变成必填 section。

## HMW 陈述（4 字段，1 条主 HMW）

| 字段 | 含义 | 引导问题 |
|---|---|---|
| situation（问题情境） | 谁 + 何时 + 卡在哪里 | 张力是什么？用户想要 vs 现实之间的落差？ |
| question（我们可以如何） | 开放问句本体 | 删光技术名词后是否仍通顺（无预设解法）？ |
| for（为/给） | 受益的具体用户 | 这条 HMW 是给谁的？ |
| so_that（以便） | 期望的可衡量结果 | 解决后世界有什么不同？如何衡量？ |

## 质量鉴别（4 维度，各判 通过/不通过）

| 维度 | 判据 | 源自 |
|---|---|---|
| preset_solution（预设解法） | 问句是否夹带解决方案而非开放问句 | 10-hmw「坏 HMW：把解决方案当问题」 |
| vague（含糊） | 是否含糊到无法行动（缺用户时刻/张力） | 10-hmw「平庸 HMW」 |
| user_moment（用户时刻） | 是否锚定具体用户时刻（谁/何时/卡住） | 10-hmw「好 HMW 三要素」 |
| tension（张力） | 是否呈现想要 vs 现实的落差 | 10-hmw「好 HMW 三要素」 |

## 想法种子（1–8 条，对齐 worksheet 的 8 想法格）

| 字段 | 含义 |
|---|---|
| content | 想法内容 |
| type | 想法类型（功能/流程/机制/体验…） |
| link_to_statement | 回应的 HMW 问句（哪条陈述） |
| status | 候选 / 已采纳 / 已弃 |

## 最低结论要求

- situation / question / for / so_that 四字段必须全部有内容或显式标为缺口
- 质量鉴别四维度必须全部判定，无未判定项
- 至少 1–2 条想法种子，且每条回应 HMW 问句而非复述

## 不得自动引入

- 不得因为模板有 8 个想法格而补写没有被讨论过的想法
- 不得把"提高效率""降低成本"扩写为日程没有讨论的内容
- 不得在四字段中补写没有被讨论过的情境、用户或结果
- 质量鉴别维度不得由 LLM 主观构造判定，必须有转写证据线索
